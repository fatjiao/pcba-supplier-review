# 供应商文件取证与比对

## 四类输入与实际读取来源

| 证据来源 | 读取和记录方式 |
| --- | --- |
| 原生原理图和 PCB | 默认 [在本机直读](native-altium.md) 支持的 Altium 二进制图档。记录文件散列、实际读取的对象、原始记录位置、有效工程范围和装配变体证据。工程级项目或取证缺口按同版导出或 AD 复核结果补足。 |
| 用户已提供的导出件 | 导出件须能对应所核板号、修订、变体和导出范围。记录原始文件及导出来源，如同版原理图 PDF、工程网表、PCB 属性表、装配图或 DRC 报告。 |
| BOM | 本机读取，记录原表工作表、行号、列及原值，展开位号后保留原行、用量和替代料关系。 |
| 公司 Checklist | 本机读取，记录名称、源表、版次、条款编号及原文所在行。旧项目的判定、备注与本次初筛分别保留。 |

同一器件可同时引用多种证据。逐格保留实际源，例如 PDF 图面的原标注、PCB 可核实的封装和 BOM 描述。图面缺少的封装或参数留空并写明来源限制。

## 来源与版本

- 只读打开供应商原文件。解包、转换、导出和测量使用独立工作目录，记录输出由哪个原文件生成，以及工具、版本和影响结果的设置。保留文件在提交包中的相对路径。归档内文件记录 `压缩包路径 → 成员路径`。
- 从发布清单、图纸标题栏和导出设置记录项目、板号、修订号及装配变体。各文件的修订标识可能采用不同规则。依据发布清单或供应商明确的映射确认它们属于同一提交版本。文件名、时间戳和文件散列可辅助定位，版本关系仍以发布依据为准。
- 版本、变体或导出范围未对齐时，继续核验依据独立的检查项。记录已看到的跨文件差异、版本边界和可能影响，结论按所在工作表口径填写。区分已确认矛盾和需要同版依据才能确认的差异。

## 在远程 Altium Designer 内取证

- 用 [本地工作副本及已验证的 RDP 传输路径](rdp.md) 在远程 AD 打开指定工程。记录本地源文件、远程工作副本及其关联批次。
- 原生读取取决于 AD 版本、工程版本和可用依赖。在隔离的工作副本打开 `.PrjPcb`，在工程树核对引用，按条款查看对象属性、网络、板层或测量值。需要批量核对时，按允许的范围生成并存放同版导出件。记录 AD 版本、选用的变体、导出设置和原始工程位置。
- 由远程 AD 导出取证所需文件，只回传该批次审核所需的证据。远程 AD 操作受阻时，已有导出件只有在能够对应到同一设计快照和导出范围时才支持相应条款。报告注明导出来源和当前远程操作状态。

## Altium Designer 提交件

- 优先读取供应商的 `.PrjPcb` 和它引用的全套 `.SchDoc`、`.PcbDoc`。结合发布信息确认层级页是否齐全、目标 PCB 和装配变体。核对原理图多通道实例的实际位号及网络作用域。涉及 ActiveBOM 或输出配置时，保留供应商提供的 `.BomDoc` 或 `.OutJob` 作为相关设置的来源。
- 仅收到单个 `.SchDoc` 或 `.PcbDoc` 时记录可读取的文件范围，工程层级、发布关系或变体由相应资料补证。
- 比较原理图与 PCB 位号时，先核对有效原理图范围。原理图独有的位号可用原生对象和渲染图核实是否完整落在已启用的编译遮罩内。以遮罩记录、图纸页码和位号说明排除依据。PDF 书签可辅助定位，书签缺项还需查看图面。 [Altium 原理图指令文档](https://www.altium.com/documentation/altium-designer/schematic/directives#compile-mask-directive)
- 原生工程打不开、缺少页面或无法可靠读取对象时，先核对用户已有的同版导出件，再按未覆盖检查要求补件。图面核对用全套原理图 PDF。跨页连接补工程网表。布局与装配按条款补 PCB 属性表、图层图、装配图或坐标。设计规则检查补同版 DRC 报告及规则配置。 [Altium 输出作业文档](https://www.altium.com/documentation/altium-designer/preparing-for-manufacture/output-jobs)

## 按文件类型取证

| 来源 | 可提取的证据 | 回查位置和局限 |
| --- | --- | --- |
| 原理图工程或网表 | 页层级、位号、元件单元、引脚、网络和器件属性。网表支持其导出范围内的电气连接核对。 | 记录层级页路径、位号及单元、引脚号和网络名。跨层级网络按工程的命名与作用域核对。网表通常缺少图纸说明和版面信息。 |
| 原理图 PDF | 图纸版本、可见符号、标注和图面相邻关系。 | 区分封面、原理图页、PCB 视图和附页。记录 PDF 实际页码、图纸页号、图框坐标及位号、引脚或网络。结合组件索引、可见文字与图像核对漏读、文字叠放、连线交点和反相标记。需要验证不可见或跨页连接时补同版工程或网表。 |
| PCB 原生工程 | 位号、封装、焊盘、网络、几何、板层、板框及工程中可读取的设计规则。 | 记录板号、位号或对象 ID、焊盘号、网络、层名及坐标。涉及距离时注明基准、单位、两端对象和测量位置。规则配置可证明检查设置，制造商能力另需对应来源。 |
| Gerber、钻孔等制造输出 | 已提供层的图形、板轮廓或孔位等导出几何，具体内容以文件和层映射为准。 | 记录导出文件名、层映射、坐标和单位。依赖孔类型、层定义或网络归属的检查需要相应属性、图纸、网表或原生工程。装配状态、设计规则和导出前的全部连接关系需要对应资料。 |
| BOM | 行项目、位号组、用量、制造商料号、封装、替代料和装配属性，以实际字段为准。 | 记录文件、工作表、物理行号及字段或单元格。保留原值和展开后的位号。核对隐藏行、筛选条件、合并区域、公式缓存和前导零是否影响解释。CSV 引用数据记录号，必要时附物理行号。 |
| 公司 Checklist | 条款原文、强制或建议属性、适用条件及原表历史字段。 | 记录工作表、行号、条款编号及版次来源。将适用性和每条结论对应到原理图、PCB、计算、实测或流程记录。 |
| 贴片坐标或装配图 | 导出范围内的装配位号、板面、坐标、旋转及图示方向。 | 记录工作表或数据行、位号、板面、坐标和单位。先确认导出的装配变体、器件排除规则、坐标原点和底层视图约定。 |
| ERC、DRC 或其他 EDA 检查报告 | 报告记录的规则执行情况与工具发现。 | 记录报告版本、规则名或编号、报告项位置及相应对象。确认报告对应的工程快照、启用的规则、检查范围和忽略项。覆盖有效且条款匹配时，才据报告给出该条款的初筛状态。 |

读本地电子表格时保留原工作表、行列、显示值和单元格类型。遇到读取失败、识别歧义或导出内容缺失时，记录具体受影响的位号、条款及所需补件。

扩展名与实际读取格式不一致时，核对当前读取路径提供的文件签名。公司保护的文件可在已授权的客户端或同版导出中取证。记录实际用于审核的字节视图，区分存储原件和可读副本的文件指纹。

## 跨文件比对

- 先确认参与比对的项目、板号、装配变体和范围。单板、拼板和多板总成按各自范围对照。位号可能在多个板实例中重用，必要时用板实例和位号组合定位。
- 根据 BOM 字段和供应商说明展开逗号分隔、范围和合并单元格等位号组。保留归一化前后的值，并验证用量是按单板、拼板还是整套计算。区分原理图多单元器件、同一位号分行列出替代料和同一比较范围内的冲突位号。无法解释的重复保留全部位置供复核。
- 使用已确认的变体装配状态解释 DNP、不贴装和可选件。检查原理图、PCB、BOM 或坐标文件间的缺项前，确认两侧预期覆盖范围，包括虚拟器件、机械件、测试点和手工装配件等。记录差异所依据的排除规则。
- 进行坐标或封装比较前，确认单位、原点、顶底面、旋转方向及底层镜像约定。检查具体引脚或焊盘时，核对符号引脚号、PCB 焊盘号和器件资料中的引脚定义。名称相同仅作为候选匹配。
- 每条差异同时引用两侧文件、具体定位及原始观测值。若某项缺失，写明检索范围、匹配键和应用的过滤条件，以便工程师重做检索。

## 写入本地工作簿的证据

- **原理图评审**。按模块保存位号、原图参数和封装来源。量化核算写工况、公式、数值及额定比较。常规器件有充分依据时给简短结论。会改变选型的假设或数据缺口放在对应器件行，系统性事项定位到最相关器件。
- **原理图Checklist**。备注包含可复查的位号、页码、规则、测量或记录。适用条款按证据判 OK 或 NG。NG 备注说明是已见差异、建议项偏离还是关键证据缺失。NC 对应有依据的不适用。
- **原理图与BOM**。按位号保存图页/图框、可用 PCB 定位和 BOM 行。明确区分图示 NC、有效装配状态、图有表无、表有图无及变体差异。逐颗保留匹配结果、替代料和无法从源图获得的字段。

工作表字段与交付顺序见 [报告格式](report.md)。两侧均保留可回查的位置和原值，便于工程师在本机报告中复核。

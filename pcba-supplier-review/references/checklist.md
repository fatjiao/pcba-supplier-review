# Checklist 条款映射

每次按项目对应的公司 Checklist 取用判定规则。可读取表格、文档或图纸中的条款。保存来源文件、名称、版次、日期和后续引用的标准。保留公司原始条款号及其语义。来源缺条款号时，使用页码与条目位置或工作表与行号生成定位标识，并标明该标识用于本次索引。

## 从条款得到可执行检查

| 字段 | 记录内容 |
| --- | --- |
| 条款 ID 与出处 | 公司条款号、版次、页码或工作表与行号。标明引用文件及其条文位置。 |
| 适用条件 | 板号或类型、变体、检查范围、例外及其判断依据。 |
| 验收要求 | 原文中的约束、单位、公差、边界和需要比对的关系。标明来自公司条款还是其引用的资料。 |
| 所需证据 | 文件类型、必要字段或对象、最低可验证粒度、跨文件对齐条件。 |
| 检查方法 | 逐项说明可执行的读取、比较、测量或人工复核步骤及结果定位。 |
| 严重度依据 | 引用公司明确规定的分级规则或记录由工程师分级。 |

- 原文为复合条款时，可将相互独立的检查点写为子项并回链原条款。冻结本次计数口径。采用子项作为计数单位时，父条款只用于汇总。相同条款的重复引用仍保留出处，只计入一次。对照适用范围中的待定、例外和人工条款，确保均进入覆盖明细。
- 将数值阈值和合同要求与供应商实测值、设计设置及工具默认值逐一对应。共同适用的公司资料之间出现冲突，或合格条件表述不明确时，标明影响范围和需工程师澄清的选择。公司明确引用的外部标准、器件规格和板厂能力文件使用适用版本及具体条文。
- 对规则配置做核对时，记录规则名、范围、约束值及启用情况。对测试或报告条款，确认测试对象、方法、覆盖、配置与修订满足要求。涉及目检、实测或工程判断时，将可整理的对象和证据交给工程师。

## 本次初筛与历史记录

按 [原理图Checklist 工作表](report.md#2-原理图checklist) 保留条款分组、编号、强制或建议级别和原文。源表的 `HW`、`评审`、`Remarks` 和示例属于原项目历史，标明来源。本次使用当前提交工件和证据填写 `AI结论` 与 `AI备注`。历史判定和备注不参与本次统计。

- **NC**。先确认适用条件，只有当前板卡、装配变体或审核范围明确没有对应对象或触发条件时才用 NC。图示预留件需结合本次范围判断该条款是否涉及预留方案或实际装配。备注给出不适用的依据。
- **OK**。现有证据支持适用要求成立。抽查时注明样本范围。要求覆盖全部对象的条款需要全范围依据。条款需要验证记录或实测时，图纸所示措施用于关联验证对象。
- **NG**。适用条款有已观察的差异、未达到原条款建议，或缺少通过所需的关键证据。适用性尚不能排除时也归 NG。备注区分差异与验证缺口，并列明应补的具体版本、装配、文件、对象或测量条件。可共享同一证据或补件，逐条保留理由和引用。

## 从资料预检转入正式初筛

记录缺少的 Checklist 或版次、适用板卡和变体，以及条款引用但尚未提供的依据。没有可采用的公司 Checklist 时，在「原理图Checklist」记录缺件和范围。可直接核查的资料矛盾留在「原理图评审」或「原理图与BOM」，保留原始位置、观测值和适用前提。收到正式依据后重新核对相关工件，并关联能够匹配的预检记录。
